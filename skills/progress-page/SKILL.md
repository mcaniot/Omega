# Progress page

One static `index.html` per mission, regenerated from a `state.json` next to it, with images or videos in `img/`, opened from `file://`. Every render registers the page in one hub, `~/.agents/progress/index.html`, that the user keeps open: tasks with a question first, then blocked, active, finished. Update at least every 2 h during a long run, or the hub flags the task "sans nouvelles". `PROGRESS_HUB` overrides the hub directory (tests).

S=~/.agents/skills/progress-page/scripts/make_page.py

1. Create the page when the mission starts, without waiting to be asked, beside the task outputs (for example `<outputs>/suivi/`), never in the scratchpad. Link both ways: first render with `--task <task> --agent <your session name>`, and add `Progress page: <dir>/state.json` to the task file.
2. Write `state.json` once (page labels and status keys are French; free text in the user's language): `title`, optional `subtitle`, `summary`, `warning`; `steps` (`step`, `status` among `fait`, `en cours`, `à faire`, `bloqué`, optional `note`); optional `sections` (`title`, `items`). Text is plain; backticks render as code. Render with `python3 $S <dir>/state.json`.
3. At each milestone, update and render in one command without reading the state, single-quoting free text (no shell expansion): `python3 $S <dir>/state.json --step '2=en cours::note' --log 'texte' --fig 'img/x.png=Titre::note'`. Steps are numbered from 1 as on the page; `N=STATUS` keeps the note, `N=STATUS::` clears it. `--add-step TEXT`, `--warn TEXT`; `--fig` paths are relative to the state directory and must exist. When waiting for the user (decision, authorization to commit or push, review), use `--ask 'question'` and leave the step `en cours` or `à faire`: `bloqué` is only for blockers outside the user's reply (resources, failures, other sessions), and nothing clears it automatically. In Claude Code the user's next prompt in your session clears it automatically (a `UserPromptSubmit` hook); log the decision (`--log 'décision : …'`) and ask again if the reply left it open. Elsewhere, your next `--step`, `--add-step`, `--fig`, `--log` or `--warn` update clears it; `--ask ''` clears it alone. Never read `index.html`.
4. Continuity: one page per mission, across sessions. Before a handoff or `/clear`, `--log 'handoff : <next action>'`. On resume (after `/clear`, compaction or a handoff), take the page from the task file's `Progress page:` line (else `python3 $S --find <task>`), never create a second one; run `--show` for the numbered steps and `--agent <your session name>`, which logs the takeover. A follow-up task on a finished page does one of two things at its start: create a new page for the new task (new directory, linked in its task file), or keep the page and add its objectives in one command, `--task <new task> --agent <name> --add-step '<objective>'...` (`--task` alone on a finished page is refused).
5. Remote viewing: `omega-progress [HOST:]PORT` serves the hub and pages read-only over HTTP and prints the tokenized URL; off loopback it publishes `http://omega.local:PORT` (mDNS, `--name`), `--open` drops the token; binding beyond `127.0.0.1` exposes them to the network, so only on the user's request.
6. Keep claims as verified as in the task file; mark unrendered or unconfirmed work as such. Prefer PNG previews at preview resolution; link a full render with a figure's `full` key.
7. A mission is finished when its task file moves to `completed/` (or, without a task, when every step is `fait`): close the task, the hub follows. Every step `fait` with the task still active for a day shows "À clôturer". The hub drops a finished mission after 7 days and an unreadable state after 14, never touching files. Its Agents section shows each session seen in 24 h (state and timeline, from the `--activity` hooks and Claude Code's session registry) and links it to the pages whose `--agent` matches its name. `python3 $S --all` re-renders every registered page; `python3 $S <state> --forget` removes a mission from the hub at once. A malformed state or flag exits non-zero with the faulty key and leaves the old page.
